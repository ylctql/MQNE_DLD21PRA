# MQNE 项目：使用与结果解读

本文介绍如何运行当前实现、查看输出，以及选择正确的恢复或重训方式。代码内部原理见 [架构与实现说明](架构与实现说明.md)。

## 1. 准备环境与运行位置

在 PowerShell 中进入项目目录：

```powershell
Set-Location 'D:\课程\博二上\量子人工智能\Project\MQNE_DLD21PRA'
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

项目 README 建议 Python 3.11 或更新版本，已有实验使用 Python 3.13.6。具体运行环境见 [environment_fixed_v2.json](../environment_fixed_v2.json)。下面命令均从项目根目录执行，并直接指定虚拟环境解释器，不要求先激活环境。

配置和输出的相对路径按当前终端目录解释；原始数据缓存由代码定位到项目根目录的 `data/`。首次 MNIST 运行需要下载数据；首次 SPT 数据生成要解一批本征问题；Numba 首次使用需要编译。pilot 减少训练规模，但不保证省去母数据的首次准备成本。

## 2. 先试运行，再启动完整搜索

试运行 Cancer：

```powershell
.\run.ps1 -Task cancer -Scale pilot -Python .\.venv\Scripts\python.exe
```

启动完整 SPT 或 MNIST 搜索：

```powershell
.\run.ps1 -Task spt -Scale fixed -Python .\.venv\Scripts\python.exe
.\run.ps1 -Task mnist -Scale fixed -Python .\.venv\Scripts\python.exe
```

`Task` 可取 `cancer`、`spt`、`mnist`。`Scale` 的 `fixed` 和 `paper` 当前选择相同的完整规模配置；`pilot` 使用小规模配置，但数据划分遵循当前固定母池协议。脚本会用时间戳建立新结果目录。

也可以直接指定配置和一个新的输出目录：

```powershell
.\.venv\Scripts\python.exe mqne.py --config configs/mnist_yao_paper.json --output results/mnist_my_search_01
```

如果该目录已存在，应换一个新名字。程序不覆盖已有实验，也不支持从中途恢复结构搜索；中断后可能留下部分配置、候选和最优模型记录。

需要保存终端日志时，可以自己重定向：

```powershell
.\.venv\Scripts\python.exe mqne.py --config configs/cancer_fixed_paper.json --output results/cancer_my_search_01 *> logs/cancer_my_search_01.log
```

完整配置默认使用 CPU 的 Numba 后端。`run.ps1 -Device cuda` 或 `mqne.py --device cuda` 会将主搜索入口切换到 PyTorch；需要本机已有可用 CUDA 环境，本项目已有复现结果未验证 GPU 表现。

## 3. 最常调整的配置

建议复制配置文件后修改，保留已有结果的原始配置。

| 配置项 | 含义 | 阅读或修改时注意 |
|---|---|---|
| `task` | 数据任务 | 决定编码维度、标签和数据处理 |
| `seed` | 搜索与训练随机种子 | 候选随机初始化时，训练种子为它加上已训练候选数 |
| `split_seed` | 固定数据划分种子 | 与搜索种子分开；更改它意味着更换数据实验条件 |
| `population` | 初代候选数；后续每个父结构产生的子候选数 | 多个幸存父结构会增加每代总候选数 |
| `survivors` | 留作下一代父结构的数量 | 不是保留并复用多少套已训练参数 |
| `generations` | 结构搜索代数上限 | 当前完整搜索为 6 |
| `initial_length` / `extension_length` | 首代门块数 / 每代追加门块数 | 门块数不等于可执行硬件线路的精确深度 |
| `epochs` / `batch_size` | 训练轮数 / 批大小 | 与 `training_unit` 一起决定更新次数 |
| `training_unit` | `epoch` 或 `step` | 前者每轮遍历训练集，后者每轮只取一个随机 batch |
| `learning_rate` | Adam 学习率 | 改变后属于不同训练设置 |
| `fitness` | `combined` 或 `validation` | 默认 combined 按训练/验证样本数加权 |
| `fitness_threshold` | 代末提前停止阈值 | 当前 1.01 表示不因准确率提前停止 |
| `evaluation_interval` | 间隔多少训练轮记录完整指标 | 不表示只在这些轮数更新参数；最后一轮也会记录 |
| `backend` / `device` | `numba` 或 `torch`；CPU 或 CUDA | Numba 仅支持 CPU |
| `input_bit_order` | `msb` 或 `yao_lsb` | 改变振幅索引与量子位编号的对应 |
| `feature_transform` | Cancer 的 `raw`、`standard`、`minmax` | minmax/standard 是预处理诊断，不是已确认的作者设置 |

`protocol="fixed_v2"` 是当前配置中的协议标识；仅改这个字段不会切换为历史数据流程，当前普通运行仍由 `datasets_v2.py` 准备数据。要了解旧实验应阅读归档材料，不要通过修改标识假装复用了旧协议。

## 4. 怎样读一个结果目录

以 [MNIST Yao 编码搜索结果](../results/mnist_yao_search_seed21/summary.json) 为例：

| 文件 | 内容 | 适合回答什么问题 |
|---|---|---|
| `config.json` | 实际运行配置 | 到底用了哪个种子、样本数和训练预算？ |
| `data_manifest.json` | 数据指纹、实际索引、预处理、位顺序 | 训练和验证是谁？能否按同样数据恢复？ |
| `candidates.json` | 每个已完成候选的结构编号、指标和历史 | 搜索训练了多少候选，各代怎样变化？ |
| `best_circuit.json` | 明确门结构、参数角度、最优候选记录与来源摘要 | 最好模型具体是什么？ |
| `best_parameters.pt` | PyTorch 参数状态文件 | 保存参数的二进制副本；当前恢复入口主要读取 JSON 中的参数 |
| `summary.json` | 完成摘要、全程最优记录、测试指标、总候选数与更新数 | 本次运行是否完成、最终表现和成本如何？ |
| `fitness.png` | 候选适应度及逐代最高适应度 | 搜索是否随代数改善？ |
| `training.png` | 最优候选的训练/验证准确率与损失 | 最优模型训练过程如何？不是全部候选的平均曲线 |
| `circuit.png` | 门块线路图 | 线路结构如何分布？由报告程序生成，普通搜索完成时不一定已有 |
| `*_predictions.csv` | 真实标签、类别 1 概率、预测标签 | 哪些样本分类错误？由恢复程序生成 |
| `restored_verification.json` | 复算指标、混淆矩阵、概率范围 | 保存材料经过恢复核验了吗？ |

`summary.json` 是当前程序完成末尾流程时写出的摘要；判断完整搜索还应结合候选数量、代数和更新预算。只有部分 `candidates.json` 或 `best_circuit.json` 的目录不应计入完整复现。

摘要中的 `best.fitness` 是结构选择分数，`best.final.validation.accuracy` 是验证准确率，`independent_test.accuracy` 是可用额外测试的准确率。Cancer 的 `independent_test` 为 `null`。准确率以 0—1 小数保存，显示为百分数时乘 100。

资源计数中 `parameters = 3 × R_gates + CRx_gates`，`block_depth` 是块数，`elementary_single_qubit_gates` 把一个 R 算作三个基础单比特旋转。不要把门块数直接等同于某一真实硬件编译后的线路深度。

混淆矩阵以真实标签为行、预测标签为列：`[[真0判0, 真0判1], [真1判0, 真1判1]]`。类别含义见架构文档第 4 节。

## 5. 恢复已有模型，不重新训练

```powershell
.\.venv\Scripts\python.exe predict.py --result results/mnist_paper_s11_yao_seed21
.\.venv\Scripts\python.exe -O predict.py --result results/mnist_paper_s11_yao_seed21
```

程序使用保存的门结构、角度和数据索引，在 PyTorch 后端复算各分区指标。全部通过后，会更新逐样本预测文件及 `restored_verification.json`，不会重新搜索或调整参数。

恢复归档模型时仍使用主目录的当前程序，例如：

```powershell
.\.venv\Scripts\python.exe predict.py --result archive/results_legacy/spt_random6_seed21
```

历史模型恢复通过只说明历史指标可重算，不会消除该历史实验原有的数据角色交叉等问题。

## 6. 重训指定结构与固定结构对照

重新训练来源合规的已保存结构：

```powershell
.\.venv\Scripts\python.exe mqne.py --config configs/mnist_yao_paper.json --circuit results/mnist_yao_search_seed21/best_circuit.json --output results/mnist_my_retrain_01
```

这里会重新初始化角度并训练一次，不是从保存的角度继续优化。来源数据、划分、预处理或位顺序不兼容时会拒绝运行。

训练论文 Fig. S11 的固定 MNIST 结构：

```powershell
.\.venv\Scripts\python.exe run_reference.py --config configs/mnist_yao_paper.json --architecture paper_s11 --seed 21 --output results/mnist_my_s11_01
```

其他结构选项为 `brickwork10`、`legacy_spt_control`，后者只支持 SPT。这个入口用于固定结构对照；已有命令使用 CPU 配置，不能将它解释为完整 MQNE 搜索的替代结果。

## 7. 核验与汇总

基础实现检查：

```powershell
.\.venv\Scripts\python.exe -m unittest test_mqne test_fixes
.\.venv\Scripts\python.exe -O -m unittest test_fixes.ProtocolTests
```

完整结果及破坏记录的端到端核验：

```powershell
.\.venv\Scripts\python.exe verify_finished.py
.\.venv\Scripts\python.exe verify_corruption.py
```

这些脚本会写入恢复输出或核验证据。`verify_finished.py` 扫描当前 `results/` 下已完成的 fixed_v2 实验；不扫描 `archive/`。`verify_corruption.py` 在临时副本中破坏验证准确率，检查普通和 `-O` 模式均失败且不生成新的预测结果。

重新生成当前复现报告：

```powershell
.\.venv\Scripts\python.exe make_fixed_report.py
```

该命令会更新报告、相关图及运行索引。它依赖代码中明确列出的 13 组实验与已有恢复材料，不是任意实验目录的通用汇总器；增加新实验后需要同步调整报告逻辑。

## 8. 常见问题

| 现象 | 通常原因与处理 |
|---|---|
| 输出目录已存在 | 为新运行换目录名；当前没有断点续搜入口 |
| 初次运行长时间没有候选完成 | 可能在下载、准备 SPT 基态、编译后端或训练首个候选；先查看终端输出 |
| `The native adjoint backend runs on CPU` | 手工配置了 Numba 与 CUDA 的不兼容组合；用主搜索入口的 `--device cuda` 切换，或保留 CPU |
| `Master partition does not match...` | 母划分与标签指纹、种子或容量不符；先核查数据与配置，不要直接改旧实验的索引 |
| `Source fingerprint differs...` | 当前源数据与保存清单不同；恢复原数据环境或调查数据变更 |
| `Restored loss/accuracy mismatch` | 保存角度、指标、数据或环境不一致；保留现场，检查四个输入 JSON 和源数据，不要修改指标使其“通过” |
| 修改 seed 后结果差别很大 | 结构抽样及初始化会变化；检查 split_seed 是否保持不变，并比较多种子表现 |
| 新实验没有出现在报告中 | 报告使用固定实验名单，需要显式加入并处理相应汇总 |

旧文件的位置与哈希记录见 [归档说明](../archive/README.md)。完整实验数值和论文结论的复现范围见 [修复与复现报告](../REPRODUCTION_FIXED_20261013.md)。
